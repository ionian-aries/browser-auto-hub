# 数据库脚本说明

平台库表与默认数据的初始化脚本。平台启动**不做 create_all**（库表须提前创建，
应用仅连接），全新部署时按编号顺序执行即可。脚本名为中文，Linux 服务器
`mysql < 文件.sql` 正常执行（文件名编码不影响执行，建议 scp/git 传输避免
Windows 中转变码）。

## 脚本清单

| 脚本 | 作用 | 默认数据 |
|------|------|----------|
| `01-建库与平台表.sql` | 创建 `browser_auto_hub` 库 + 平台 5 表（pipelines / schedules / task_executions / task_logs / system_settings），按外键依赖顺序 | 见下方「自动写入」 |
| `02-创建inbox_documents沟通待办表.sql` | 沟通待办业务表（todos 写入 / forward 消费），与平台表无 FK，但需 01 已建库 | **无需种子**：采集自动写入，按 `task_id` 唯一去重 |
| `03-默认数据-每10分钟采集待办调度.sql` | 向 schedules 写入「每 10 分钟采集沟通待办」的 interval 调度 | 含 INSERT（幂等） |

## 执行顺序与前提

```bash
mysql -uroot -p < 01-建库与平台表.sql
mysql -uroot -p < 02-创建inbox_documents沟通待办表.sql
# 启动一次后端（自动同步 pipelines 表），然后：
mysql -uroot -p < 03-默认数据-每10分钟采集待办调度.sql
```

- 01 / 02 纯建表（`IF NOT EXISTS`，可重复执行）；02 的 `USE` 依赖 01 已建库，按编号顺序执行即可
- 03 依赖 pipelines 表已有 `oa.communicate_todos` 行（后端启动时自动同步），
  因此**先启动一次后端再执行**；若影响行数为 0 即此前提未满足，启动后端后重跑
- 03 幂等：已存在同 pipeline + 600s interval 的调度时跳过插入

## 哪些表自动写入，哪些需要种子

| 表 | 数据来源 |
|----|----------|
| pipelines | 后端启动自动同步代码注册的 pipeline，**无需种子** |
| task_executions / task_logs | 每次触发/执行自动写入，**无需种子** |
| system_settings | 代码对 `run_*` 键均有默认值兜底，页面保存后才落行，**无需种子** |
| inbox_documents | todos 采集自动写入，**无需种子** |
| schedules | **需要种子**（03）或页面/API 创建 |

## 脚本中「值」的含义

**DDL 列默认值**（01/02 内，插入时应用不传也有值）：

| 位置 | 值 | 含义 |
|------|----|----|
| 各表 `created_at` / `updated_at` | `DEFAULT (utc_timestamp())` | 当前 UTC 时间 |
| `task_logs.timestamp` | `DEFAULT (utc_timestamp(6))` | 当前 UTC 时间，微秒精度 |
| `pipelines.status` | `DEFAULT 'active'` | 新同步流水线默认可触发 |
| `inbox_documents.fwd` / `skip` | `DEFAULT 0` | 未转发/不跳过；采集 INSERT 不传这两列靠默认值兜底——MySQL 严格模式下缺它会整批失败（历史事故，见 spec 3） |

**03 种子值**：

| 值 | 含义 |
|----|----|
| `'每10分钟采集沟通待办'` | 调度名称（展示用） |
| `'interval'` + `600` | 固定间隔触发，600 秒 = 10 分钟 |
| `JSON_OBJECT('username','your_oa_username',...)` | 执行入参，**占位符**，必须替换为真实 OA 凭据 |
| `enabled = 0` | 默认停用——占位凭据下启用会每 10 分钟刷一条失败执行，填好凭据后再启用 |
| `max_retries = 0` / `retry_delay_seconds = 60` | 失败不自动重试（间隔 60s，改 max_retries 才生效） |

## 注意事项

- 时间语义：`created_at` 等列存 **UTC**（`utc_timestamp()` 默认）；`run_at` /
  `forward_time` 同为 UTC
- 首次触发时机：interval 调度在**启用后一个间隔**首次触发（不会启用即执行）
- 同库中若存在 `documents` 等其他表，属于共用 MySQL 实例上的其他项目，与本平台无关，
  本目录脚本不含、也不应操作这些表
- 删执行记录走平台 API（`DELETE /api/executions/{id}`，会先清 task_logs 再删记录），
  不要直接删 `task_executions` 行——FK 约束会报错
