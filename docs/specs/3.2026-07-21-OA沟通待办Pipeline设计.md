# OA 沟通待办采集 Pipeline 设计

> 日期：2026-07-21
> 状态：待实施
> 依赖：spec 1（平台架构）
> 2026-07-23 修订：config_schema 移除 3 个运行设置类参数（page_load_timeout /
> element_visible_timeout / action_settle_timeout）——它们属于全局运行设置层
> （system_settings run_*，runner 三级覆盖链注入：全局打底、execution.config 可覆盖），
> 不属于 pipeline 自身属性；pipeline 代码仍全量支持这 3 个参数及 headless/close_browser。
> 同时表单展示顺序规则：username 最前、password 其次，其余随后——由前端 SchemaFields
> 排序实现（spec 4 §4.4），因 MySQL JSON 会按 key 长度+字典序重排 properties，
> schema 声明顺序无法作为展示依据。
> 2026-07-24 修订：附件 URL 由 MinIO 预签名改为**平台代理下载地址**（spec 1 二十三次
> 修订）——url 字段存 `{PUBLIC_BASE_URL}/api/files/{object_key}` 绝对 URL，永不过期；
> 消费方使用方式不变（读 attachment_urls 直接 GET 下载）。
> 2026-07-24 修订（二）：(1) `attachment_urls` 元素简化为**纯 URL 字符串数组**
> （原 {filename, object_key, url, ok} 对象数组），仅收录上传成功项——失败附件由
> stats.attachment_failures 计数 + 步骤日志记录，不入数组；(2) object_key 拼接去掉
> 硬编码 `/attachments/` 段，改为 `{minio_object_prefix}/{task_id}/{filename}`——
> 前缀完全决定存储路径（对齐 MINIO_OBJECT_PREFIX=attachments 配置；旧拼接在
> prefix=attachments 下会产生 attachments/attachments 双层重复）。
> 2026-07-24 修订（三）：采集流程改为「列表级去重 + href 直达详情 + 复核熔断」。
> 原流程打开详情页后才从 URL 取 task_id 去重——每条已存在记录也耗费一次详情页
> 打开（约 3s/条），漂移窗口大；新消息置顶导致列表位移，造成同一条目重复打开、
> 采集期间新进消息本轮丢失（只能等下次调度）。新流程：
> (1) 列表页直接从标题链接 href 提取 fdId 去重（href 无 fdId 的个别条目延迟到
> 详情页 URL 判定），未知条目记录 {task_id, href}，不再为已知条目开详情页；
> (2) 详情页经 goto(href) 直达，免疫列表位移；
> (3) 详情采集后做列表级完整复核，发现新条目则继续采集，最多 3 轮熔断，
> 仍有流入则记 warn、留待下次调度自愈；
> (4) 单条详情失败降级为 extract_failures 计数 + 日志，不再中断整个执行。
> result_summary 新增 extract_failures 键，其余对外契约（config / 表结构）不变。
> (5) `oa_browser` 改为显式 `browser.new_context()`：Playwright 1.61 中
> `browser.new_page()` 创建的隐式 context 禁止在其上再 `new_page()`
> （报错 "Please use browser.new_context()"），详情直达标签页依赖该能力；
> 显式 context 为 Playwright 推荐模式，两 OA pipeline 行为不变（同 context 标签共享会话）。
> (6) 复核轮次上限暴露为 config 键 `max_verify_rounds`（默认 3，入 schema）。
> 并发详情采集暂不引入：单轮新条目通常极少，收益不抵复杂度；「先收集后统一
> 开详情」的结构已为后续加 concurrency 键铺好路。
> 2026-07-24 修订（四）：(1) pipeline_sync 仅在
> version 变化时覆盖 DB 中的 config_schema（spec 1 §4.5），修订（三）新增
> `max_verify_rounds` 但未提升 version，导致 pipelines 表仍是旧 schema、前端
> 执行配置表单不显示该字段。（后续：spec 1 二十七次修订将 sync 改为内容对比，
> 该前提已消除，version bump 不再必要——见修订五「另」。）
> (2) 新增 config 键 `concurrency`（integer，默认 1）：详情页并发采集数——
> 同一 browser context 内并行打开的标签页上限，asyncio.Semaphore 限流 +
> asyncio.gather 收集一轮 pending。共享状态并发安全：步骤日志写库走同一
> AsyncSession（不可并发），`existing_ids` 延迟去重的 check-then-add 跨 await
> 有竞态，两者统一用一把 asyncio.Lock 串行；stats 计数自增无 await 交错，安全；
> MinIO 上传为同步调用会阻塞事件循环（附件小，可接受）。默认 1 时行为与串行
> 完全一致；调大需自行评估 OA 限流风险。
> (3) `max_verify_rounds` 默认值 3 → 2（用户决定：一轮复核足以覆盖常规流入，
> 多轮留给显式配置）。
> 2026-07-24 修订（五）：共享登录 `oa_login` 增加导航失败处理（todos/forward
> 共用，spec 5 同步适用）。真实故障链（生产复现确认）：OA 冷状态登录 302 跳转
> IAM SSO 地址（iam-sit.sd-port.net:18010，SIT 环境地址，当前网络 NXDOMAIN）
> → chromium 停在 chrome-error:// 页；旧轮询只认 portal / login_error 两种
> URL，干等满 15s 报误导性 "Login did not complete within timeout"。
> 已实证排除「检测到失败后直连 portal」方案：未认证访问 portal 同样 302 到
> IAM（服务端在 302 前不种会话 cookie），再次 DNS 失败。已实证「完整重试登录」
> 可行：首次尝试虽客户端失败，但服务端 SSO 状态已建立，二次尝试走本地认证
> 直达 portal（生产 2 例 + 本地 3 例复现均成立，重试登录 ~2s 成功）。
> 新行为：轮询检测 chrome-error:// → 立即判定导航失败（不再等满 15s）→
> 自动完整重试 1 次；仍失败抛 LoginTimeout（可重试类），错误消息含真实原因；
> LoginError（凭据错误）不触发重试。SSO 地址不可达属 OA 服务端配置问题，
> 应另行向 OA 运维报告，本修订仅为平台侧韧性兜底。
> 另：修订（四）针对「忘 bump version 导致 DB 漂移」的教训，已由 spec 1
> 二十七次修订（sync 改为逐字段内容对比）从机制上消除——version 仅作溯源
> 标记，忘 bump 不再导致 DB 漂移；本 pipeline version 维持 1.0.0，不再 bump。
> 2026-07-28 修订（六）：(1) `id` 由 CHAR(36) UUID 改为 **BIGINT 自增主键**——
> 对齐生产环境外部建表（skill_custom_inbox_documents.id 为 bigint AUTO_INCREMENT），
> engine 写入不再显式生成 UUID，由数据库自增赋值。(2) task_id 语义明确为
> **文档 fdId**（详情页落地 URL 中的标识）：OA 通知列表 href 中的 fdId 是
> 通知记录 ID，与文档 ID 不同；采集一律以重定向后落地 URL 为准，列表级
> fdId 仅作本轮预过滤（原实现直接采用列表 href fdId，导致 forward showid 无效，
> OA 报「该文档不存在」）。(3) 新增索引 idx_inbox_documents_fwd_send
> (fwd, send_time)（对齐生产）。(4) 修正 DDL 漂移：fwd/skip 改 NOT NULL DEFAULT 0；
> collation utf8mb4_0900_ai_ci → utf8mb4_unicode_ci（与平台其他表一致）；
> UNIQUE KEY 命名 uk_task_id → 默认命名 task_id。
> 2026-07-28 修订（七）：fwd 取值语义扩展——`0` 未转发、`1` 已转发（历史值，
> 旧系统/早期平台回写）、`2` 已转发（本平台 forward pipeline 回写，2026-07-28 起）。
> forward 前置校验仅以 fwd=2 为幂等跳过条件；fwd=0/1/NULL 均照常执行，
> 成功后覆盖为 2（详见 spec 5 2026-07-28 修订）。

## 1. 概述

将现有 `browser-agent/scripts_v3/oa_communicate_todos.py` 迁移为 browser-auto-hub 平台的第一个正式 Pipeline，支持定时/API/手动三种触发方式。

### 1.1 功能

- 登录 OA 系统（支持 login.jsp 直接登录和 IAM OAuth SSO）
- 遍历沟通待办列表（含分页）
- 逐条打开详情，提取元数据
- 下载附件并上传至 MinIO，生成平台下载 URL（`/api/files/{object_key}`）
- 按 task_id 去重后写入 MySQL `inbox_documents` 表
- 全程通过 StepLogger 记录步骤日志 + SSE 推送（平台截图链路已于 spec 1 十七次修订退役；附件上传 MinIO 属本 pipeline 业务行为，保留）

### 1.2 非目标（本次不做）

- 转发功能（`fwd` 字段由后续 pipeline 处理）
- cookie 缓存/session 复用

```python
    config_schema={
        "type": "object",
        "properties": {
            "username": {"type": "string", "description": "OA 用户名"},
            "password": {"type": "string", "format": "password", "description": "OA 密码"},
            "login_url": {
                "type": "string",

                "description": "OA 登录页地址"

            "max_pages": {
                "type": "integer",
                "default": 100,
                "description": "最大采集页数（防止死循环）"
            },
            "max_verify_rounds": {
                "type": "integer",
                "default": 2,
                "description": "详情采集后列表级复核的最大轮数（抓采集期间新进消息；熔断防死循环）"

            "concurrency": {
                "type": "integer",
                "default": 1,
                "description": "详情页并发采集数（同一 context 内并行标签页上限；调大需评估 OA 限流）"

        },

class OaCommunicateTodosPipeline(BasePipeline):
    async def execute(self, config: dict, ctx: ExecutionContext) -> PipelineResult:
        ...
```

> 运行设置类参数（`headless` / `close_browser` / `page_load_timeout` /
> `element_visible_timeout` / `action_settle_timeout`）**不在 schema 中声明**：

> pipeline 代码经 `config.get(...)` / `setdefault` 全量消费。

## 5. ExecutionContext

Runner 在调用 `pipeline.execute()` 前组装上下文，pipeline 无需自行管理基础设施连接：

```python
@dataclass
class ExecutionContext:
    logger: StepLogger          # 步骤日志（写 DB + SSE 广播）
    db: AsyncSession            # SQLAlchemy async session（平台 DB）
    minio: MinioClient          # MinIO 客户端（封装 boto3）
    settings: Settings          # 平台配置（readonly）
    execution_id: str           # 当前执行 ID（UUID v4）
```

## 6. 执行流程

```
触发 → runner.run(pipeline_name, config, execution_id)
│
├── 更新 task_executions.status = "running"
├── 实例化 OaCommunicateTodosPipeline
├── 构建 ExecutionContext
├── pipeline.execute(config, ctx):
│   │
│   ├── step: "launch_browser"
│   │   playwright.chromium.launch(headless=True)
│   │
│   ├── step: "login"
│   │   from engine.pipelines.oa.shared.login import oa_login
│   │   oa_login(page, config)
│   │
│   ├── step: "locate_list"
│   │   等待 portal_qdport.jsp iframe 就绪
│   │   检测空状态 → 若空则提前返回
│   │
│   ├── step: "crawl"（主扫描，列表级，2026-07-24 修订三）
│   │   for each page:
│   │     从标题链接 href 提取 fdId → 对照 existing_ids 去重（不开详情页）
│   │     未知条目记录 {task_id, href}；href 无 fdId 者 task_id 置 None 延迟判定
│   │     翻页 (fingerprint 防死循环)
│   │
│   ├── step: "extract"（仅新条目，修订三；concurrency 并发，修订四）
│   │   Semaphore(concurrency) 限流 + gather：同 context 并行标签页
│   │   goto(href) 直达详情（免疫列表位移）→ 提取元数据
│   │   下载附件 → ctx.minio.upload → 生成平台下载 URL（/api/files/{key}）
│   │   日志写库 / 延迟去重由 asyncio.Lock 串行（共享 AsyncSession 不可并发）
│   │   单条失败：extract_failures 计数 + 日志，继续下一条
│   │
│   ├── step: "verify"（复核熔断，最多 max_verify_rounds 轮默认 2，修订三/四）
│   │   重载列表回第 1 页 → 列表级完整重扫
│   │   有新条目 → 回 extract；无 → 结束；超轮上限 → warn，留待下次调度
│   │
│   ├── step: "save"
│   │   过滤已存在 task_id (去重)
│   │   INSERT INTO inbox_documents (新记录)
│   │   通过 ctx.db 执行
│   │
│   └── 关闭浏览器
│
├── 更新 task_executions.status = "success" / "failed"
└── 记录 result_summary: {total, inserted, skipped, attachment_failures, extract_failures}
```

## 7. 数据库模型

### 7.1 inbox_documents 表

```sql
CREATE TABLE inbox_documents (
  id BIGINT NOT NULL AUTO_INCREMENT COMMENT '自增主键',
  task_id VARCHAR(64) NOT NULL COMMENT 'OA 文档 fdId（详情页落地 URL 中的标识，非列表 href 中的通知 ID）',
  creator VARCHAR(255) DEFAULT NULL COMMENT '发起人',
  send_time VARCHAR(64) DEFAULT NULL COMMENT '发送时间（页面原文，如 2026-07-21 08:00）',
  title TEXT NOT NULL COMMENT '标题',
  participants TEXT NOT NULL COMMENT '接收者（逗号分隔）',
  cc_recipients TEXT NOT NULL COMMENT '抄送人（逗号分隔）',
  summary TEXT COMMENT '正文摘要',
  attachment_urls TEXT NOT NULL COMMENT '附件下载 URL（JSON 字符串数组，仅上传成功项）',
  fwd TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否已转发: 0未转发 1已转发(历史) 2已转发',
  `skip` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否跳过: 0正常 1跳过',
  forward_time DATETIME DEFAULT NULL COMMENT '转发完成时间（UTC）',
  PRIMARY KEY (id),
  UNIQUE KEY task_id (task_id),
  KEY idx_inbox_documents_fwd_send (fwd, send_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 7.2 去重策略

写入前通过 `SELECT task_id FROM inbox_documents` 加载已有 ID 集合，新记录中已存在的 task_id 直接跳过（不 INSERT）。使用 UNIQUE KEY 作为最终防线。

## 8. 触发方式

### 8.1 定时触发

通过前端创建 schedule：

```json
{
  "pipeline_id": "<oa.communicate_todos 的 ID>",
  "name": "工作日早8点采集OA待办",
  "trigger_type": "cron",
  "cron_expr": "0 8 * * 1-5",
  "config_override": {
    "username": "ceshiyong4",
    "password": "***"
  },
  "enabled": true
}
```

APScheduler 根据 cron 表达式到时间后触发 runner。

### 8.2 API 触发

```
POST /api/executions
{
  "pipeline": "oa.communicate_todos",
  "config": {
    "username": "ceshiyong4",
    "password": "***"
  }
}

Response 201:
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "pipeline": "oa.communicate_todos",
  "status": "pending",
  "created_at": "2026-07-21T08:00:00Z"
}
```

### 8.3 手动触发

前端 Pipeline 详情页 → 点击"立即执行" → 弹出配置表单（根据 config_schema 动态渲染 username/password 字段）→ 提交 → 调用同一 API。

## 10. 浏览器策略

| 决策 | 选择 |
|------|------|
| 实例管理 | 每次执行启动全新实例；headless 与结束后是否关闭均为**可配置**（config.headless / config.close_browser，默认 true/true，可被全局运行设置与触发覆盖改变，见 spec 4 §8.2 九次修订） |
| 运行模式 | 默认 headless（生产）；headed 仅限本地调试（Docker 环境无 GUI） |
| Playwright 版本 | 使用平台 pyproject.toml 中统一管理的版本 |
| 浏览器类型 | Chromium（Playwright 内置） |

## 11. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 浏览器管理 | 每次新实例 headless | 无状态、Docker 友好、避免 session 残留 |
| 登录 | 每次重新登录 | 简单可靠、无 cookie 管理开销 |
| 去重 | task_id UNIQUE + 预查询跳过 | 幂等、重复运行安全 |
| 数据存储 | 直接写 MySQL inbox_documents | 不产中间文件 |
| 公共逻辑 | oa/shared/ 目录 | OA 域共享、不参与注册扫描 |
| 附件 | 上传 MinIO → 平台下载 URL（/api/files/{key}） | 复用平台 MinIO 配置；URL 永不过期 |
| DB 访问 | 通过 ExecutionContext 注入 AsyncSession | pipeline 无需自行管理连接 |
| MinIO 访问 | 通过 ExecutionContext 注入 | 统一配置、统一生命周期 |
| 采集方式 | 逐页扫描；列表级去重 + goto(href) 直达详情（concurrency 并发，默认 1）+ 最多 max_verify_rounds 轮复核熔断（默认 2）（2026-07-24 修订三/四） | 不为已知条目开详情页（漂移窗口秒级）；直达导航免疫新消息置顶位移；复核抓采集中新进消息，熔断后由下次调度自愈 |
