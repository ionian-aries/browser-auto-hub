# Browser Auto Hub 前端重设计

> 日期：2026-07-21
> 状态：待实施
> 依赖：spec 1（平台架构）、spec 3（OA Pipeline）

---

## 1. 概述

### 1.1 目标

重新设计 Browser Auto Hub 前端，以"Dashboard 看板"为核心，提供：
- 实时任务状态总览（运行中/已完成/失败）
- Pipeline 管理与调度配置一体化
- 手动触发 → 自动跳转执行详情 → SSE 实时日志调试
- 系统设置（存储/运维/调度控制）

### 1.2 用户画像

两种模式兼顾：
- **开发调试阶段**：深度日志、截图预览、错误定位、实时 SSE 推送
- **上线运维阶段**：状态看板、成功率统计、异常告警

### 1.3 设计原则

- Pipeline 详情页整合调度管理（调度从属于 Pipeline，不独立）
- 业务数据（inbox_documents）不在前端展示，通过日志 + result_summary 上报摘要
- 手动触发路径最短：触发 → 跳转详情 → 看实时结果
- 所有 ID 为 UUID 字符串（与后端对齐）
- 浏览器策略由 Pipeline 代码自行控制，平台不干预

### 2.3 变更说明

~~去掉独立的"调度管理"导航项~~（八次修订逆转）：调度仍从属于 Pipeline（创建时必须选定 Pipeline），
但新增 `/schedules` 全局页用于跨 Pipeline 查看/启停/编辑/删除所有调度——运维视角需要
"现在系统里都有哪些定时任务在跑"的统一答案，逐个进 Pipeline 详情页翻 Tab 不可接受。

### 2.4 整体布局规范

- **全局 CSS reset**：`html, body, #root { margin: 0; height: 100% }`（此前项目无任何 CSS 文件，浏览器默认 body 8px margin 在页面最外层形成白边）
- **视口等高布局**：外层 Layout 固定 `height: 100vh`，页面不随内容撑高
- **侧边栏固定**：Sider 始终停留在视口左侧，不随内容滚动（菜单过多时自身 overflow auto）
- **内容区内部滚动**：滚动条出现在右侧 Content 容器（符合"哪里内容多哪里滚"的直觉），而非 window 级滚动
- Content 使用 padding 24（而非 margin），使滚动条贴合视口右缘；内部白卡 `min-height: 100%`

### 2.5 侧边栏选中态规范（十次修订新增）

- 侧边栏选中项仅由**导航页路由**决定；无匹配导航项的瞬态页
  **不得选中任何菜单项**——此前无匹配时回退选中「看板」，造成"点击立即执行却高亮看板"的错觉
- 瞬态交互优先用弹窗而非路由页承载（十一次修订：执行配置 `/run` 页已废除改回弹窗，
  根因消除；本规则保留作为后续新增瞬态页的约束）

## 4. Pipeline 列表页 `/pipelines`

### 4.1 展示方式

卡片网格（每行 3 张，响应式）。每张卡片：
- Pipeline 显示名 + 状态 Tag（active/disabled）
- 描述（单行截断 ellipsis）
- 触发方式 Tags（cron / api / manual）
- 最近一次执行：状态 Tag + 相对时间
- 底部操作栏：「立即执行」+「定时设置」（ClockCircleOutlined，直接打开该 Pipeline 的新建调度 Modal，无需先进入详情页）
- 点击卡片标题 → 跳转 `/pipelines/:name`

### 4.2 触发方式全集

Pipeline 的全部触发场景与对应机制：

| 场景 | 机制 | 入口 |
|------|------|------|
| 立即执行一次（调试/补数） | 手动创建 Execution（trigger_type="manual"） | 卡片/详情页「立即执行」 |
| 指定未来某时刻执行一次（如凌晨回补） | Schedule trigger_type="once" + run_at | 「定时设置」/ 调度管理 |
| 周期规律执行（每天 8 点、每周一、每月 1 号） | Schedule trigger_type="cron" + cron_expr | 「定时设置」/ 调度管理 |
| 固定间隔轮询（每 5 分钟） | Schedule trigger_type="interval" + interval_seconds | 「定时设置」/ 调度管理 |
| 外部系统回调触发 | POST /api/executions（trigger_type="api"） | API |

一个 Pipeline 可同时挂载多条调度（如工作日 8 点 + 周末 10 点各一条 cron）。

### 4.3 手动触发交互（智能判断）

1. 检查 `config_schema.required` 是否有字段
2. **有 required** → 弹出配置表单 Modal → 确认后创建 Execution（trigger_type="manual"）→ navigate 到 `/executions/:id`
3. **无 required** → 直接创建 Execution（使用 schema 中的 default 值，trigger_type="manual"）→ navigate 到 `/executions/:id`

### 4.4 动态表单渲染（基于 config_schema）

| JSON Schema 类型 | 渲染组件 | 规则 |
|------------------|----------|------|
| `type: "string"` | Input | 有 default 则预填 |
| `type: "string"` + description 含"密码" | Input.Password | 自动识别 |
| `type: "integer"` | InputNumber | 有 default 则预填 |
| label | 取 `description` 字段 | fallback 取 property key |

仅渲染 `config_schema.properties` 中的字段，`required` 数组中的字段标记为必填。

**三级覆盖链**（九次修订）：字段默认值 = 全局运行设置（system_settings run_*，若存在）
→ 否则 schema default；用户提交的值最终覆盖二者。runner 执行前将全局运行设置合入
config 底层（`{**global_run, **execution.config}`），保证未显式覆盖的维度走全局默认。

### 4.5 统一执行配置弹窗（十一次修订：/run 页废除，改回弹窗）

> 十一次修订逆转九/十次修订的"独立页面"方案：`/run` 页面跳转后侧边栏无任何导航项
> 可定位选中（§2.5 只能做到"不高亮"，无法做到"合理归属"），体验割裂。弹窗内嵌
> Tabs 后已能承载分组表单，弹窗载体不再构成阻碍。

立即执行与定时设置共用同一弹窗 `RunModal`：

- **入口**（均为打开弹窗，不发生路由跳转）：流水线卡片「立即执行」「定时设置」、
  Pipeline 详情页按钮、调度管理页「新建调度」、调度「编辑」
- **弹窗结构**（宽 880px，Tabs 分组；各 Tab 内容按宽度 2~3 栏网格排布）：
  - 顶部（固定流水线入口不显示；全局新建调度入口显示）：流水线 Select
  - **Tab 1：流水线参数**（默认激活）——当前 Pipeline config_schema 的 SchemaFields
    （默认值按三级覆盖链预填），双栏网格
  - **Tab 2：执行方式**——Radio 立即执行 / 定时调度；选定时展开调度区块（调度名称、
    触发方式 cron/interval/once、cron 预设、重试次数与间隔——默认值取全局运行设置）
  - **Tab 3：运行配置**——平台运行行为（无头模式、结束后关闭浏览器，默认取全局运行设置）
  - 底部：确定按钮常驻（文案随执行方式：立即执行 / 保存调度）；提交校验失败时
    自动切换到第一个错误字段所在 Tab
  - 字段补充说明：控件下方小字灰显、**最多两行**（line-clamp 2），不再使用 tooltip
    （十一次修订逆转十次修订的 tooltip 方案——说明文字应直接可见）
- 提交：立即执行 → 创建执行并跳转详情；定时 → 创建/更新调度并跳转调度管理页（编辑模式
  停留在当前页刷新列表）
- 后端 `GET /api/schedules/:id` 供 edit 模式回显（保留）

### 4.6 流水线筛选与启停（十一次修订新增）

- **筛选栏**（`/pipelines` 顶部，前端筛选）：名称关键字（匹配 display_name/name）、
  触发方式（cron/api/manual）、状态（启用/停用）
- **启停 Switch**（卡片上直接切换）：`PATCH /api/pipelines/:name` 扩展允许 `status`
  字段（active/disabled）；停用语义：
  - 卡片「立即执行」「定时设置」禁用
  - `POST /api/executions` 对停用流水线返回 400
  - 调度器触发时跳过停用流水线（已有调度 job 保留但不产生执行）
  - 列表 API 返回**全部状态**（此前仅 active——停用项必须可见可管理）
- **看板同步**（§3.1）：「流水线总数」卡片改为「启用 X / 共 Y」

## 5. Pipeline 详情页 `/pipelines/:name`

### 5.1 页面头部

- Pipeline 显示名 + 状态 Tag
- 「立即执行」按钮（同 4.2 逻辑）

### 5.2 Tab 布局（3 个 Tab）

#### Tab 1：概览

基本信息卡片（Descriptions 组件）：
- 标识（name）
- 描述
- 触发方式
- 最大并发数（max_concurrent）— 可编辑（InputNumber + 保存按钮）
- 执行超时（timeout_seconds）— 可编辑（InputNumber + 保存按钮，显示换算分钟）
- 创建时间

配置模板（可折叠）：
- config_schema 以格式化 JSON 展示

编辑 max_concurrent / timeout_seconds 调用 `PATCH /api/pipelines/:name`（新增 API）。

#### Tab 2：调度管理

该 Pipeline 下的调度列表表格（后端必须按 `pipeline_id` 过滤）：
- 列：名称、触发类型（cron/interval/once）、表达式/间隔/执行时刻、启用 Switch、下次执行时间、操作（编辑/删除）
- Switch 直接调用 `PATCH /api/schedules/:id/toggle`
- 「新建调度」按钮 → Modal 表单
- **CRUD 即时同步调度器**：create/update/toggle/delete 在写库后立即调用 SchedulerManager 对应方法注册/更新/摘除 job，无需重启
- **下次执行时间**：后端返回列表时按 trigger 实时计算（`trigger.next()`），不写库

调度 Modal 表单字段：
- 名称（必填）
- 触发类型（Radio：cron / interval / once，中文标签：Cron 定时 / 固定间隔 / 单次定时）
- cron 设置（trigger_type=cron 时显示）——**预设引导，不要求手写表达式**：
  - 频率 Radio：每天 / 工作日（周一至周五）/ 每周 / 每月 / 自定义
  - 每天、工作日：TimePicker（HH:mm）
  - 每周：星期 Select（周一~周日）+ TimePicker
  - 每月：日期 InputNumber（1-31）+ TimePicker
  - 自定义：Input 原生 cron 表达式（高级用户出口）
  - 预设选择自动生成 5 段 cron 表达式（如每天 08:30 → `30 8 * * *`）并实时展示
- 间隔秒数（trigger_type=interval 时显示）
- 执行时刻（trigger_type=once 时显示，DatePicker 带时分，禁用过去时间）
- 运行参数——**复用 config_schema 动态表单**（抽取 SchemaFields 组件，与立即执行
  ExecuteModal 共用同一渲染逻辑）：按 Pipeline 的 config_schema 逐字段渲染，
  提交为 config_override；Pipeline 无 schema 时不显示此区块
- 最大重试次数（InputNumber，默认 0）
- 重试间隔秒数（InputNumber，默认 60）

**once（单次定时）机制**：
- schedules 表新增 `run_at DATETIME(6) NULL` 列（无 alembic，启动时检查 information_schema 自动 ALTER 补列）
- `_build_trigger` 使用 `DateTrigger(run_time)`；库中存 UTC-naive，构造时转为本地时区 aware
- 触发执行后自动 `enabled = False`（重启后 sync_all 不会重复注册；列表中显示为停用）
- 创建/更新校验：once 必须提供 run_at 且不得早于当前时间（宽限 1 分钟），否则 400

#### Tab 3：执行历史

该 Pipeline 的执行记录表格（分页 20 条/页）：
- 列：状态 Tag、触发方式、开始时间、耗时、重试次数
- 点击行 → 跳转 `/executions/:id`

### 5.3 全局调度管理页 `/schedules`

跨 Pipeline 的调度总表（八次修订恢复独立导航）：
- 列：名称、流水线（display_name 中文名，Link 跳详情）、类型、表达式/间隔/时刻、
  启用 Switch、下次执行时间、操作（编辑/删除）
- 「新建调度」按钮 → 同一 ScheduleModal，但增加流水线 Select（选定后按其 config_schema
  渲染运行参数表单）
- 编辑/删除/启停与 Pipeline 详情页 Tab 行为一致（即时同步调度器）

### 5.4 流水线名称显示规范

- 列表/详情/调度/看板等所有展示位置一律使用 `display_name`（中文显示名）
- 标识符 `name`（如 `oa.communicate_todos`）仅用于路由链接与 API 参数，不直接展示
- 后端 ExecutionResponse / ScheduleResponse 同时返回 `pipeline_name`（路由用）与
  `pipeline_display_name`（展示用）

## 6. 执行详情页 `/executions/:id`

### 6.1 页面头部

- Pipeline 名称（Link 跳回 Pipeline 详情）+ 执行 ID（缩略显示前 8 位）
- 状态 Tag（实时更新）+ 触发方式 + 开始时间 + 耗时
- 「取消执行」按钮（仅 pending/running 时显示）

### 6.2 主体布局 — 左右分栏（7:3）

#### 左侧：实时日志流

- **running 状态**：通过 SSE (`GET /api/executions/:id/logs/stream`) 实时推送
  - 新日志自动追加
  - 自动滚动到底部（用户手动滚动上方时暂停自动滚动）
- **已完成状态**：一次性加载历史日志 (`GET /api/executions/:id/logs`)
- 每条日志格式：`[时间] [step标签] [level图标] 消息内容`
  - step 标签：不同 step 不同颜色（自动分配）
  - level 图标：info=蓝色圆点、warn=橙色三角、error=红色叉
  - error 级别整行红色背景高亮
- 顶部过滤栏：级别筛选（全部 / info / warn / error）

#### 右侧：执行信息面板

按以下顺序展示（Card 形式堆叠）：

1. **执行结果**（成功时）：result_summary JSON 格式化展示
2. **错误信息**（失败时）：error_message 红色区域展示
3. **执行配置**：本次传入的 config（折叠 JSON，密码字段显示 ***）
4. **产出文件**：artifacts 列表（文件名 + 大小 + 下载按钮）
5. **截图预览**：日志中带 screenshot_key 的条目列出缩略图（通过 `GET /api/files/presign?key=<screenshot_key>` 获取预签名 URL），点击 Modal 放大

### 6.3 SSE 连接生命周期

```
页面加载 → 请求执行详情
    ├── status = "pending" → 轮询执行详情（refetchInterval 3s），转为 running 后走 SSE 分支
    ├── status = "running" → 建立 SSE 连接
    │   ├── 收到日志 → append to list
    │   └── 收到 {type: "complete"} → 关闭 SSE → refetch 执行详情
    └── status ∈ {success, failed, cancelled} → 请求历史日志
```

> 注意：pending 必须纳入轮询——后端无排队机制，pending→running 为毫秒级，
> 但若详情页只在 running 时轮询/连 SSE，落在 pending 的页面将永远停留在「排队中」（死端）。

## 7. 执行记录页 `/executions`

### 7.1 顶部筛选栏

| 筛选项 | 组件 | 说明 |
|--------|------|------|
| 流水线 | Select（可选全部） | 筛选特定 Pipeline |
| 状态 | Select multiple（中文选项） | 多选为 **OR** 语义（命中任一即展示）；后端按 `status.in_(...)` 过滤 |
| 时间范围 | RangePicker + showTime（精确到时分） | 按 created_at **服务端筛选**（start/end 参数），不做前端当前页过滤 |

### 7.2 表格

| 列 | 说明 |
|----|------|
| 流水线 | 中文显示名 pipeline_display_name（Link 按标识符跳 Pipeline 详情）；后端必须填充 |
| 状态 | Tag 彩色标签，**中文**（排队中/运行中/成功/失败/已取消） |
| 触发方式 | **中文**（手动触发/定时触发/API 触发） |
| 开始时间 | started_at 格式化 |
| 耗时 | finished_at - started_at |
| 重试次数 | retry_count（0 则不显示；调度失败自动重试产生的执行 >0） |
| 结果 | 成功显示 result_summary 单行预览；**失败显示 error_message 截断**；无则 "-" |
| 操作 | 「删除」（Popconfirm 确认；仅终态可删，pending/running 需先取消） |

- 点击行 → 跳转 `/executions/:id`
- 删除：`DELETE /api/executions/:id`——pending/running 返回 400（提示先取消）；
  **仅删除执行记录 + task_logs + task_artifacts 元数据行**（FK 约束要求），
  **MinIO 中的截图/产物文件与 pipeline 写入的业务数据一律保留**；
  Popconfirm 文案必须与此语义一致，不得暗示文件被删除；
  **Popconfirm 必须包一层 `span onClick=stopPropagation`**（十一次修订 bug 修复：
  React portal 的合成事件沿组件树而非 DOM 树冒泡，确认按钮的点击会冒泡到行 onClick
  导致删除后误入详情页）

### 8.3 保存与持久化机制

- MinIO 六项 + 运维两项 → `system_settings` 表；重启后由 `get_merged_settings()` 合并 DB 值覆盖 .env 默认值，即时生效
- MinIO **热更新**：所有 MinIO 使用点（runner 执行、step_logger 截图、files 预签名、连接测试）均在每次使用时按合并配置构造 `MinioStorage`，保存后立即生效，无需重启；`ctx.settings` 亦注入合并配置
- `database_url` **不存 DB**（鸡生蛋问题：settings 表本身在数据库里）→ 写穿透到 `.env` + 运行时热切换 engine
- 不脱敏原则：平台无登录认证，所有配置项（含 `minio_secret_key`、`database_url` 密码）GET 均返回真实值
- 全部即时生效：连接配置（MinIO 合并构造 / database_url 热切换）与运维策略（调度器开关即时 pause/resume、保留天数由每日清理任务每次运行时读取）均保存即生效，无需重启

## 10. 技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| UI 框架 | Ant Design 5 | 已在用，组件丰富 |
| 状态管理 | React Query（服务端状态）+ useState（局部） | 轻量，不需要 Redux |
| 路由 | react-router-dom v6 | 已在用 |
| HTTP 客户端 | axios | 已在用 |
| SSE | 原生 EventSource | 轻量够用，已验证 |
| 动态表单 | 手写 JSON Schema → Ant Form 映射 | config_schema 结构简单，不引入重库 |
| 枚举显示 | 前端共享映射层 `labels.ts`：status（排队中/运行中/成功/失败/已取消）、trigger_type（手动触发/定时触发/API 触发）、pipeline status（启用/停用）、schedule type（Cron 定时/固定间隔） | 后端枚举值保持英文存储，前端任何展示位不得直接渲染原始枚举 |
| 类型 | 所有 id 类型改为 `string` | 与后端 UUID 对齐 |
| 自动刷新 | React Query refetchInterval（5s） | Dashboard + 执行列表 |
| 样式 | Ant Design token（ConfigProvider：zhCN 语言包 + colorPrimary/borderRadius）+ 灰底（#f5f5f5）白卡布局 + dayjs zh-cn | 不引入 Tailwind；无 ConfigProvider 时组件内置文案（分页/日期/空态/弹窗按钮）为英文 |
| 时间处理 | DB 统一存 UTC naive；模型层 `UTCDateTime` TypeDecorator 读出时标记 tzinfo=UTC，API 序列化输出带 `+00:00` 的 ISO 8601 | 无时区后缀的 ISO 会被浏览器按本地时间解析，导致 UTC+8 环境显示晚 8 小时；后端一处根治，前端 `new Date()` 自动转本地 |
