## 1. 概述

### 1.1 目标

重新设计 Browser Auto Hub 前端，以"Dashboard 看板"为核心，提供：
- 实时任务状态总览（运行中/已完成/失败）
- Pipeline 管理与调度配置一体化
- 手动触发 → 自动跳转执行详情 → SSE 实时日志调试
- 系统设置（存储/运维/调度控制）

### 1.2 用户画像

两种模式兼顾：
- **开发调试阶段**：深度日志、截图预览、错误定位、实时 SSE 推送
- **上线运维阶段**：状态看板、成功率统计、异常告警

### 1.3 设计原则

- Pipeline 详情页整合调度管理（调度从属于 Pipeline，不独立）
- 业务数据（inbox_documents）不在前端展示，通过日志 + result_summary 上报摘要
- 手动触发路径最短：触发 → 跳转详情 → 看实时结果
- 所有 ID 为 UUID 字符串（与后端对齐）
- 浏览器策略由 Pipeline 代码自行控制，平台不干预

### 2.4 整体布局规范

- **全局 CSS reset**：`html, body, #root { margin: 0; height: 100% }`（此前项目无任何 CSS 文件，浏览器默认 body 8px margin 在页面最外层形成白边）
- **视口等高布局**：外层 Layout 固定 `height: 100vh`，页面不随内容撑高
- **侧边栏固定**：Sider 始终停留在视口左侧，不随内容滚动（菜单过多时自身 overflow auto）
- **内容区内部滚动**：滚动条出现在右侧 Content 容器（符合"哪里内容多哪里滚"的直觉），而非 window 级滚动
- Content 使用 padding 24（而非 margin），使滚动条贴合视口右缘；内部白卡 `min-height: 100%`
- **浏览器标签图标**（三十三次修订新增；2026-07-24 重设计）：`public/favicon.svg`——
  蓝紫渐变圆角浏览器窗口 + 三节点流程连线（中间节点内嵌播放符，自动化执行意象），
  index.html `<link rel="icon" type="image/svg+xml">` 引入；标签标题保持 "Browser Auto Hub"

### 2.5 侧边栏选中态规范（十次修订新增）

- 侧边栏选中项仅由**导航页路由**决定；无匹配导航项的瞬态页
  **不得选中任何菜单项**——此前无匹配时回退选中「看板」，造成"点击立即执行却高亮看板"的错觉
- 瞬态交互优先用弹窗而非路由页承载（十一次修订：执行配置 `/run` 页已废除改回弹窗，
  根因消除；本规则保留作为后续新增瞬态页的约束）

### 2.6 列表页统一设计语言（二十二次修订新增）

流水线 / 调度管理 / 执行记录三个列表页采用同一套增删改查布局：

- **页面骨架**：根容器固定视口可用高度（`calc(100vh - 96px)`，同 §6.2 等高约定），
  flex 纵向：页头标题 → 筛选栏 → 表格区 `flex:1; min-height:0`。
  **表格出现滚动条，页面不出现滚动条**。
- **筛选栏**（两端布局 `flex + space-between`）：
  - 左侧：筛选项组。每项 = 查找项名称（灰色文字）+ 控件。
    **控件选型（二十三次修订）：能用选择器就不用输入框**——名称类用可搜索单选
    Select（`showSearch`），枚举类用 Select；可多值过滤的枚举（触发方式、类型、状态等）
    用**多选 Select**（OR 语义）；时间范围用 RangePicker
  - 右侧：统一「筛选」主按钮（SearchOutlined）+ 页面级动作（如「新建调度」）
  - **草稿语义**：筛选控件改动不即时生效，点击「筛选」才应用（重置到第 1 页）；
    清空控件后点「筛选」即恢复全量
- **数据表格**：
  - 表头固定（`scroll.y`），表体固定高度占满剩余空间，内部滚动
  - **占满机制**（二十三次修订）：ResizeObserver 测量表格容器高度，表体滚动高 =
    容器高 − 表头(39) − 分页(64)；内容不足一页时以 min-height 撑满，**分页始终贴底**，
    不随内容高度收缩
  - 列宽固定分配，**不提供列显隐开关**；不设 `scroll.x`——列宽按内容区宽度预算分配
    （一列弹性 + ellipsis），避免横向滚动条
  - 分页完整配置：`showTotal`（共 N 条）、`showSizeChanger`（10/20/50/100）、`showQuickJumper`；
    服务端分页（执行记录）与前端分页（流水线/调度）行为一致
- **说明文字统一 tooltip**（全局规则，见 §8.1）：表单项补充说明一律 label 后缀
  icon + Tooltip，不再置于控件下方

### 4.2 触发方式全集

Pipeline 的全部触发场景与对应机制：

| 场景 | 机制 | 入口 |
|------|------|------|
| 立即执行一次（调试/补数） | 手动创建 Execution（trigger_type="manual"） | 卡片/详情页「立即执行」 |
| 指定未来某时刻执行一次（如凌晨回补） | Schedule trigger_type="once" + run_at | 「定时设置」/ 调度管理 |
| 周期规律执行（每天 8 点、每周一、每月 1 号） | Schedule trigger_type="cron" + cron_expr | 「定时设置」/ 调度管理 |
| 固定间隔轮询（每 5 分钟） | Schedule trigger_type="interval" + interval_seconds | 「定时设置」/ 调度管理 |
| 外部系统回调触发 | POST /api/executions（trigger_type="api"） | API |

一个 Pipeline 可同时挂载多条调度（如工作日 8 点 + 周末 10 点各一条 cron）。

### 4.3 手动触发交互（智能判断）

1. 检查 `config_schema.required` 是否有字段
2. **有 required** → 弹出配置表单 Modal → 确认后创建 Execution（trigger_type="manual"）→ navigate 到 `/executions/:id`
3. **无 required** → 直接创建 Execution（使用 schema 中的 default 值，trigger_type="manual"）→ navigate 到 `/executions/:id`

### 4.4 动态表单渲染（基于 config_schema）

**核心原则**（十八次修订）：渲染器选择**完全由 schema 类型声明驱动**，禁止按
property 名称/描述文字特化。pipeline 作者在 config_schema 中声明类型与 format，
前端 SchemaFields 按下表机械映射——新 pipeline 无需任何前端改动即获得正确控件。

| JSON Schema 声明 | 渲染组件 | 规则 |
|------------------|----------|------|
| `type: "string"` | Input | 有 default 则预填 |
| `type: "string"` + `format: "password"` | Input.Password | **声明式**（十八次修订废除 description 含"密码"/字段名启发式——名称特化）；pipeline 密码字段必须声明 format |
| `type: "string"` + `format: "textarea"` | Input.TextArea（3 行） | 长文本 |
| `type: "string"` + `enum: [...]` | Select | 选项来自 enum，杜绝非法值 |
| `type: "integer"` / `type: "number"` | InputNumber | 有 default 则预填 |
| `type: "boolean"` | Switch | valuePropName=checked |
| `type: "array"` + `items.type: "string"` | Select mode="tags" | 回车/逗号录入，原生字符串数组提交，不经 JSON |
| `type: "array"`（复杂 items）/ `type: "object"` | JSON 编辑器（TextArea 多行等宽字体，占满整行） | 表单内存字符串，rules 校验 JSON 合法性，提交前 JSON.parse 回原生类型；编辑回显时序列化；可选字段留空则不提交该键（十七次修订） |
| label | 取 `description` 字段 | fallback 取 property key |

**复杂参数引导**（十八次修订）：JSON 编辑器类字段应在 schema 中提供 `default`
作为**结构示例（demo）**——预填完整可编辑样例（如 forwards 预填一条含全部
可选键的示例项），用户在其上修改，无需凭空猜测嵌套结构。字段文档从
`items.properties` 逐字段生成 `键：description（必填）`，以 label 后缀
icon + Tooltip 呈现（二十二次修订：由编辑器下方 hint 改为 tooltip，JSON 不支持
注释，字段文档以此方式呈现，同样类型驱动、无需特化）。

仅渲染 `config_schema.properties` 中的字段，`required` 数组中的字段标记为必填。

**展示排序的唯一名称特化例外**（二十五次修订）：凭据类字段展示置顶——key 含
`username` 的字段最前、含 `password` 的其次，其余字段保持原相对顺序。理由：
MySQL JSON 存储会按 key 长度+字典序重排 `properties`，schema 声明顺序无法经
DB 同步传到前端；而用户名/密码是 OA 类 pipeline 用户首要填写项。此例外仅影响
展示顺序，不影响控件选型（控件仍完全类型驱动）。

**系统设置页的例外说明**（十八次修订）：`/settings` 各表单键集合封闭、由平台
定义（非用户可扩展），按 key 逐个硬编码控件，但每个控件与其值类型一致
（secret→Password、int→InputNumber、bool→Switch）。若未来设置项改为动态扩展，
须同样改为类型驱动。

**三级覆盖链**（九次修订）：字段默认值 = 全局运行设置（system_settings run_*，若存在）
→ 否则 schema default；用户提交的值最终覆盖二者。runner 执行前将全局运行设置合入
config 底层（`{**global_run, **execution.config}`），保证未显式覆盖的维度走全局默认。

### 6.2 主体布局 — 左右分栏（7:3）

**等高 100% 布局**（十六次修订）：页面根容器固定为视口可用高度

#### 左侧：实时日志流

- **running 状态**：通过 SSE (`GET /api/executions/:id/logs/stream`) 实时推送
  - 新日志自动追加
  - 自动滚动到底部（用户手动滚动上方时暂停自动滚动）

  - level 图标：info=蓝色圆点、warn=橙色三角、error=红色叉
  - error 级别整行红色背景高亮

#### 右侧：执行信息面板

按以下顺序展示（Card 形式堆叠）：

1. **执行结果**（成功时）：result_summary JSON 格式化展示
2. **错误信息**（失败时）：error_message 红色区域展示
3. **执行配置**：本次传入的 config（折叠 JSON，密码字段显示 ***）

> 2026-07-23 四次修订：随 spec 1 十七次修订（库表精简）同步——task_artifacts 表与截图链路退役，删除「产出文件」与「截图预览」两个卡片；`GET /api/files/presign` 一并下线。

### 6.3 SSE 连接生命周期

```
页面加载 → 请求执行详情
    ├── status = "pending" → 轮询执行详情（refetchInterval 3s），转为 running 后走 SSE 分支
    ├── status = "running" → 建立 SSE 连接
    │   ├── 收到日志 → append to list
    │   └── 收到 {type: "complete"} → 关闭 SSE → refetch 执行详情
    └── status ∈ {success, failed, cancelled} → 请求历史日志
```

> 注意：pending 必须纳入轮询——后端无排队机制，pending→running 为毫秒级，
> 但若详情页只在 running 时轮询/连 SSE，落在 pending 的页面将永远停留在「排队中」（死端）。

### 8.3 保存与持久化机制

- 运行设置（run_*）+ 运维两项 → `system_settings` 表；每次使用时实时读取，保存即生效
- MinIO 五项（endpoint/access_key/secret_key/bucket/object_prefix）+ `public_base_url`（平台对外地址，三十二次修订随 spec 1 二十三次修订替代 presign_expires_seconds）**仅存 `.env`**（十九次修订起不再入 system_settings）；pipeline 侧每次使用按 `.env` 值构造 MinIO 客户端
- `database_url` **仅存 `.env`**（鸡生蛋问题：settings 表本身在数据库里），修改 = 编辑 `.env` + 重启/重建容器；二十一次修订起不再经 API 暴露
- 运行旋钮全部即时生效：调度器开关即时 pause/resume、保留天数由每日清理任务每次运行时读取、run_* 由 runner 每次执行实时读取，均保存即生效、无需重启

## 9. 新增后端 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/system/info` | 运行状态（scheduler 真实状态、活跃调度数） |
| GET | `/api/system/settings` | 获取所有运行旋钮当前值（仅 system_settings 表键集合，二十一次修订起不再返回 database_url） |
| PUT | `/api/system/settings` | 批量更新运行旋钮（仅接受 system_settings 表键集合） |
| GET | `/api/executions/stats` | 执行统计（today_count、success_rate、running_count） |
| PATCH | `/api/pipelines/:name` | 启停 Pipeline（仅 `status`；三十次修订起 max_concurrent/timeout_seconds 退役） |

### 9.1 `/api/executions/stats` 响应

```json
{
  "today_count": 12,
  "today_success": 10,
  "today_failed": 2,
  "success_rate": 0.83,
  "running_count": 1
}
```

"今日"定义：本地时区当天 00:00:00 起至当前时刻（与业务日切割一致，spec 1 §14）。

### 9.2 `/api/system/info` 响应

```json
{
  "scheduler_status": "running",
  "active_schedules": 3
}
```

`scheduler_status` 取自 SchedulerManager 的真实暂停标记（非恒 running）。该接口由系统设置页「运维策略」Tab 消费。

### 9.3 `system_settings` 表

```sql
CREATE TABLE system_settings (
  `key` VARCHAR(100) PRIMARY KEY,
  `value` TEXT NOT NULL,
  updated_at DATETIME DEFAULT NOW() ON UPDATE NOW()
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

初始记录：

| key | value | 说明 |
|-----|-------|------|
| `log_retention_days` | `30` | 日志保留天数 |
| `scheduler_enabled` | `true` | 调度器开关 |

> 十九次修订：`minio_*` 六键不再入 system_settings（收归 `.env` 唯一来源）；
> `run_*` 运行设置键（§8.2 Tab 0）亦存此表，此处从略。

注意：`database_url` 不在此表，持久化到 `.env`。

### 9.4 `PATCH /api/pipelines/:name` 请求

```json
{
  "status": "disabled"
}
```

仅允许修改 `status`（active/disabled，启停，§4.6），其他字段由代码注册决定不可改。
（三十次修订：max_concurrent/timeout_seconds 随功能退役从请求模型移除）

## 10. 技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| UI 框架 | Ant Design 5 | 已在用，组件丰富 |
| 状态管理 | React Query（服务端状态）+ useState（局部） | 轻量，不需要 Redux |
| 路由 | react-router-dom v6 | 已在用 |
| HTTP 客户端 | axios | 已在用 |
| SSE | 原生 EventSource | 轻量够用，已验证 |
| 动态表单 | 手写 JSON Schema → Ant Form 映射 | config_schema 结构简单，不引入重库 |
| 枚举显示 | 前端共享映射层 `labels.ts`：status（排队中/运行中/成功/失败/已取消）、trigger_type（手动触发/定时触发/API 触发）、pipeline status（启用/停用）、schedule type（Cron 定时/固定间隔） | 后端枚举值保持英文存储，前端任何展示位不得直接渲染原始枚举 |
| 耗时显示 | 前端共享工具 `formatDuration(seconds)`：`45秒` / `1分23秒` / `2小时3分`；看板时间线、执行记录、Pipeline 执行历史、执行详情四处统一调用，禁止各处内联重复计算（十六次修订） | 此前 4 处各自内联（格式不一致：纯秒 vs m s），重复代码 |
| 类型 | 所有 id 类型改为 `string` | 与后端 UUID 对齐 |
| 自动刷新 | React Query refetchInterval（5s） | Dashboard + 执行列表 |
| 样式 | Ant Design token（ConfigProvider：zhCN 语言包 + colorPrimary/borderRadius）+ 灰底（#f5f5f5）白卡布局 + dayjs zh-cn | 不引入 Tailwind；无 ConfigProvider 时组件内置文案（分页/日期/空态/弹窗按钮）为英文 |
| 时间处理 | DB 统一存 UTC naive；模型层 `UTCDateTime` TypeDecorator 读出时标记 tzinfo=UTC，API 序列化输出带 `+00:00` 的 ISO 8601 | 无时区后缀的 ISO 会被浏览器按本地时间解析，导致 UTC+8 环境显示晚 8 小时；后端一处根治，前端 `new Date()` 自动转本地 |

## 11. 使用路径汇总

### 路径 1：查看系统状态
`/ (Dashboard)` → 看统计卡片 + 运行中任务卡片 + 最近时间线

`/pipelines` → 点击「立即执行」→ （有必填则弹窗填 config）→ 自动跳转 `/executions/:id` → 实时看 SSE 日志

`/` Dashboard 看到失败 → 点击进入 `/executions/:id` → 左侧日志找 error → 右侧看 error_message

### 路径 5：查看执行历史
`/executions` → 按 Pipeline/状态/时间筛选 → 点击行进入详情

### 路径 6：调整系统配置
`/settings` → 切换到对应 Tab → 修改参数 → 保存

### 路径 7：启停 Pipeline
`/pipelines` → 状态列 Switch 直接切换（或 `/pipelines/:name` → Tab 1 概览查看状态）
