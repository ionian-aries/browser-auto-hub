## 1. 项目概述

### 1.1 定位

Browser Auto Hub 是一个**浏览器自动化任务管理平台**，提供：
- Pipeline 注册与管理（高码开发，代码级自动发现）
- 定时/API/手动 三种触发方式
- 实时执行监控（步骤日志 + 截图 + SSE 推送）
- 文件产出管理（MinIO 存储）
- Docker 一键部署

### 1.2 核心场景

- 数据采集：从目标网站自动采集结构化数据
- 表单填写：模拟人工操作填写在线表单
- 浏览器自动化：点击、导航、翻页等自动化操作
- 任务编排：多步骤 Pipeline 顺序执行

### 1.3 非目标（POC 阶段不做）

- Pipeline 上传/下载（高码模式无需）
- 用户权限管理/多租户
- 分布式 worker 扩展
- 低代码/拖拉拽 Pipeline 编辑器

## 4. Pipeline 注册机制

### 4.1 设计原则

- **代码即配置**：Pipeline 通过 Python 装饰器声明元数据
- **启动时自动发现**：backend 启动时扫描 `engine/pipelines/` 目录
- **数据库同步**：发现的 Pipeline 元数据同步到 MySQL（用于前端查询和调度关联）

### 4.2 Pipeline 基类

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Literal

@dataclass
class PipelineMetadata:
    name: str                          # 唯一标识符
    display_name: str                  # 前端显示名
    description: str                   # 描述
    trigger_modes: list[Literal["cron", "interval", "api", "manual"]]
    config_schema: dict | None = None  # JSON Schema，描述可配置参数

class BasePipeline(ABC):
    metadata: PipelineMetadata

    @abstractmethod
    async def execute(self, config: dict, logger: StepLogger) -> PipelineResult:
        """执行 Pipeline，通过 logger 记录步骤日志"""
        ...
```

### 4.3 注册装饰器

```python
def register_pipeline(**kwargs):
    """装饰器：注册 Pipeline 到全局 registry"""
    def decorator(cls):
        cls.metadata = PipelineMetadata(**kwargs)
        PipelineRegistry.register(cls)
        return cls
    return decorator
```

### 4.4 示例 Pipeline

```python
@register_pipeline(
    name="oa_communicate_todos",
    display_name="OA 沟通待办采集",
    description="采集 OA 系统沟通待办列表及详情，产出 JSONL 文件",
    trigger_modes=["cron", "api", "manual"],
    config_schema={
        "type": "object",
        "properties": {
            "username": {"type": "string"},
            "password": {"type": "string"},
            "concurrency": {"type": "integer", "default": 1, "minimum": 1, "maximum": 10},
        },
        "required": ["username", "password"]
    }
)
class OaCommunicateTodosPipeline(BasePipeline):
    async def execute(self, config: dict, logger: StepLogger) -> PipelineResult:
        logger.step("login", "登录 OA 系统")
        # ... 执行逻辑
        logger.step("extract", "提取待办列表")
        # ...
        return PipelineResult(success=True, artifacts=[...])
```

## 12. 执行日志与监控

### 9.1 StepLogger

Engine 提供结构化日志接口：

```python
class StepLogger:
    def __init__(self, execution_id: int):
        self.execution_id = execution_id

    async def step(self, name: str, message: str, level: str = "info",
                   screenshot: bytes | None = None):
        """记录一个步骤日志，可选附带截图"""
        # 1. 如有截图，上传到 MinIO
        # 2. 写入 task_logs 表
        # 3. 通过 SSE 广播给订阅该 execution 的前端

    async def error(self, name: str, message: str, screenshot: bytes | None = None):
        await self.step(name, message, level="error", screenshot=screenshot)
```

### 9.2 SSE 广播机制

```python
# 内存中维护 execution_id -> set[queue] 的映射
# 前端订阅时创建 asyncio.Queue，退出时移除
class LogBroadcaster:
    _subscribers: dict[int, set[asyncio.Queue]]

    def subscribe(self, execution_id: int) -> asyncio.Queue: ...
    def unsubscribe(self, execution_id: int, queue: asyncio.Queue): ...
    async def publish(self, execution_id: int, log_entry: dict): ...
```

### 9.3 截图策略

- Pipeline 执行每个关键步骤后自动截图（headless 模式下 Playwright 支持截图）
- 截图存入 MinIO：`screenshots/{execution_id}/{step_name}_{timestamp}.png`
- 日志记录关联截图的 MinIO key
- 前端通过 `/api/files/:id/download` 代理获取

## 10. playwright-cli 集成方案

playwright-cli 是 Node.js CLI 工具，在 Python engine 中通过 subprocess 调用：

```python
class PlaywrightCliExecutor:
    """通过 subprocess 调用 playwright-cli 命令"""

    async def run_command(self, command: str, args: list[str]) -> str:
        proc = await asyncio.create_subprocess_exec(
            "playwright-cli", command, *args,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
        )
        stdout, stderr = await proc.communicate()
        if proc.returncode != 0:
            raise PlaywrightCliError(stderr.decode())
        return stdout.decode()

    async def open_page(self, url: str, session: str = "default") -> None:
        await self.run_command("goto", [url, f"--session={session}"])

    async def snapshot(self, session: str = "default") -> str:
        return await self.run_command("snapshot", [f"--session={session}"])

    async def click(self, ref: str, session: str = "default") -> None:
        await self.run_command("click", [ref, f"--session={session}"])
```

Docker 镜像中需同时安装 Node.js 和 playwright-cli：
```dockerfile
# 在 Dockerfile.backend 中额外安装
RUN apt-get install -y nodejs npm && npm install -g @playwright/cli
```

Pipeline 可选择使用 browser-use（纯 Python）或 playwright-cli（通过 subprocess），根据具体任务需求选择执行器。

## 11. 关键设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 后端语言 | Python | browser-use/CloakBrowser 都是 Python，避免跨语言通信 |
| 中间层 | 无 BFF | 单后端服务，无需接口聚合 |
| 任务调度 | APScheduler | 低并发场景，无需分布式 Celery |
| Pipeline 注册 | 代码装饰器 + 自动发现 | 高码模式，pipeline 就是代码 |
| 实时展示 | SSE + 截图 | 替代有头模式，服务器 headless 也能"看到"执行过程 |
| 架构 | 单容器（backend + engine 同进程） | 低并发，asyncio + executor 足够 |
| Monorepo 管理 | uv workspace + pnpm workspace | Python/Node 各用各的包管理器 |
| 数据库 | MySQL + SQLAlchemy 2.0 async | 成熟稳定，FastAPI 社区标配 |
| 对象存储 | MinIO | S3 兼容、自托管、Docker 一键部署 |

## 13. 数据流

```
用户操作                     系统行为
────────                     ────────
[前端] 手动触发 Pipeline  →  POST /api/executions
                              → backend 创建 execution 记录 (status=pending)
                              → backend 在 asyncio executor 中启动 engine.runner
                                  → runner 实例化 Pipeline 类
                                  → Pipeline.execute() 开始执行
                                      → 每步通过 StepLogger 记录
                                      → StepLogger 写 DB + 发 SSE
                                      → 产出文件上传 MinIO + 记录 artifact
                                  → 执行完成/失败，更新 execution status
[前端] SSE 订阅日志流     ←  GET /api/executions/:id/logs/stream
                              → 实时接收步骤日志 + 截图 URL
```

```
[APScheduler] cron 触发   →  scheduler callback
                              → 与手动触发相同的后续流程
```

```
[外部系统] API 触发       →  POST /api/executions
                              → 与手动触发相同
                              → 返回 execution_id 供轮询状态
```
