- 状态：已实施
- 日期：2026-07-22
- 前置文档：

## 1. 目标与定位

将独立脚本 `oa_communicate_forward.py` 100% 迁移为平台 pipeline `oa.communicate_forward`，
复用平台的注册、调度、runner（超时/并发/重试）、SSE 日志、MinIO、DB 等全部基础设施。

**批量语义**：config 中 `forwards` 为数组，一次执行共用**一次浏览器启动 + 一次登录**，
串行逐条转发（与 todos 一致，避免 OA 限流）。

**事务语义（与 todos 的关键差异）**：转发是对 OA 系统的真实副作用操作。
每条 submit 成功后**立即独立 commit** `fwd=1`，不依赖 runner 的最终统一 commit——
保证进程崩溃/超时后 DB 状态与 OA 真实状态一致，杜绝重复转发事故。

## 2. 非目标

- 不支持 `submit=false`  Dry-Run（源脚本参数，按需求取消，总是真实提交）
- 不并发转发（串行逐条）
- 不处理附件内容转发（OA 转发表单自动携带原附件）
- 不做 cookie 缓存 / 会话复用（每次执行重新登录）
- 不支持 cron 调度（task_id 为一次性消费，无周期意义）

## 3. 文件结构

```
packages/engine/src/engine/pipelines/oa/
├── __init__.py
├── communicate_todos.py        # 改造: 改用 shared/browser.py（行为不变）
├── communicate_forward.py      # 新增, @register_pipeline(name="oa.communicate_forward")
└── shared/
    ├── __init__.py             # 导出 oa_login, LoginError, LoginTimeout, oa_browser
    ├── login.py                # 不动
    └── browser.py              # 新增: 统一浏览器启动/关闭
```

共享层只放真正跨 pipeline 的内容（login、browser）。
forward 的步骤函数（导航/填表/提交/DB 回写）为 forward 专属，
按 `communicate_todos` 先例作为私有函数内联在 `communicate_forward.py` 中。

注册机制零改动：`discover()` 递归扫描自动注册，`.shared.` 模块自动跳过。

## 4. shared/browser.py

```python
@asynccontextmanager
async def oa_browser(config: dict) -> AsyncIterator[Page]:
    """启动 Chromium, yield page, 自动关闭。"""
```

- 从 `communicate_todos.py` 内联启动逻辑原样抽取：
  `async_playwright()` → `chromium.launch(headless=...)` → `browser.new_page()`。
- `headless` 支持 config 覆盖，默认 `True`。
- `close_browser` 支持 config 覆盖，默认 `True`；`False` 时保留浏览器进程（调试用，与 communicate_todos 同名参数语义一致）。
- `communicate_todos` 改为 `async with oa_browser(config) as page:`，行为完全不变（回归测试保证）。

## 6. 执行流程

```
execute(config, ctx):
1. setdefault 超时默认值
2. 校验 forwards 非空、每项 task_id 与 recipients 齐全
   → 校验失败返回 PipelineResult(success=False)，不启动浏览器
3. async with oa_browser(config) as page:
4. step "login" → oa_login(page, config)
   → LoginError / LoginTimeout: 整体 failed
5. for item in forwards（串行）:
     step "forward[{task_id}]"
     a. 前置校验（实时 SELECT，非预载）:
        SELECT fwd, forward_time FROM inbox_documents WHERE task_id=%s
        - missing → failed+1, log error, continue（不打开表单页）
        - 已转发  → skipped+1, log info, continue
     b. _goto_forward(page, task_id, config)
        导航 kmCollaborateMain.do?method=add&showForward=true&showid={task_id}
        等待 input[name=docSubject] 可见
     c. _fill_form(page, item, config)
        标题(非空才覆盖) / 紧急 checkbox / recipients 逐个 _pick_one / cc_recipients 逐个 _pick_one
        （_pick_one 原样移植: 键入触发搜索 → 等待唯一可见候选 → 禁止歧义自动选 → 隐藏 ids input 变化确认）
     d. _submit_and_verify(page)
        点击提交 → 轮询所有标签页捕获「您的操作已成功」
     e. _update_fwd(ctx, task_id) + await ctx.db.commit()   ← 逐条独立提交
        原子 UPDATE inbox_documents SET fwd=1, forward_time=%s
        WHERE task_id=%s AND (fwd IS NULL OR fwd=0) AND forward_time IS NULL
        forwarded+1
     单项 try/except Exception:
        failed+1, logger.step(level="error", screenshot=await page.screenshot()), continue
6. result_summary = {total, forwarded, skipped, failed, errors: [{task_id, error}]}
   success = (failed == 0)
```

### 6.1 逐条 commit 的安全性论证

`ctx.db` 是 runner 共享的 AsyncSession。中途 commit 的影响：

- 顺带提交 pending 的 TaskLog 行——无害且有益（日志更早落库可见，SSE 推送不受影响）
- execution 行的 `status=running / started_at` 已在 runner 开始阶段 commit，不受影响
- runner 从不 rollback，finally 中再 commit 一次——两次 commit 无冲突
- 后续 item 失败或 `asyncio.wait_for` 超时取消任务时，已 commit 的 fwd=1 永久生效

备选方案"ExecutionContext 增加 session_factory 开独立 session"被否决：
改动 engine/backend 契约，收益不抵成本。

### 6.2 前置校验必须实时查询

不能开工时一次性预载 fwd 状态集合：长批次执行中外部状态可能变化。
由于每条都 commit、session 无未提交事务，实时 SELECT 总读到最新已提交状态。

## 7. 底层存储与 logger 对接

| 能力 | 来源 | 用法 |
|------|------|------|
| DB | `ctx.db`（AsyncSession） | 原始 SQL（与 todos `_save_records` 同模式）；每条 UPDATE 后立即 commit |
| MinIO | 不直接使用 | 失败截图经 `ctx.logger.step(screenshot=...)` 由 DbStepLogger 统一上传 |
| 日志 | `ctx.logger`（StepLogger） | 源脚本全部 `print` 替换为结构化 step 日志；每条待办独立 step；错误用 `level="error"` |
| 配置 | `config` + `ctx.settings` | 平台 config_schema 注入，无独立 config.json |

## 8. 错误处理

| 场景 | 行为 |
|------|------|
| config 校验失败 | 整体 failed，不启动浏览器 |
| LoginError（凭据错误） | 整体 failed，不重试（不可重试错误） |
| LoginTimeout | 整体 failed（可由 schedule 的 max_retries 重试） |
| 单条 missing（未采集） | 该条 failed，继续后续 |
| 单条已转发 | 该条 skipped，继续后续 |
| 单条浏览器/表单/提交异常 | 该条 failed + 错误截图，继续后续 |
| 人名候选 >1（歧义） | RuntimeError → 该条 failed（禁止自动选，与源脚本一致） |
| 人名未找到 | RuntimeError → 该条 failed（与源脚本一致） |

## 9. 测试

- config 校验：缺 forwards / 缺 task_id / 空 recipients → failed 且不启动浏览器
- 前置校验三态：pending / forwarded / missing → 对应执行 / skipped / failed 分支（fake session）
- 批量流程：mock page 与步骤函数，验证
  - 一次 login、逐条串行
  - 每条成功后 commit 被调用一次
  - 单项失败隔离（后续 item 继续执行）
  - stats 聚合（total / forwarded / skipped / failed / errors）
  - 原子 UPDATE 的 SQL 形态（含 WHERE 防重条件）
- todos 改造回归：现有测试全绿
